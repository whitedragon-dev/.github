# Contributing to WhiteDragon-dev

Thank you for your interest in contributing to WhiteDragon-dev.

WhiteDragon-dev builds minimal, focused software for the open web. Contributions are welcome when they improve a project while preserving its simplicity, clarity, and purpose.

## Before Contributing

Please read the repository's:

- `README.md`
- `LICENSE`
- project-specific documentation, if available

For substantial changes, open an issue or discussion first. Small fixes, documentation improvements, and obvious bug fixes may be submitted directly.

## Our Principles

### Keep it minimal

Prefer simple solutions over unnecessary frameworks, dependencies, abstractions, or infrastructure.

### Keep it clear

Code should be readable, maintainable, and consistent with the existing project.

### Keep it focused

A pull request should address one coherent change whenever possible. Avoid unrelated refactoring or formatting changes.

### Respect the project

Each WhiteDragon-dev repository may have different goals, architecture, and licensing. Follow the conventions and requirements of the project you are contributing to.

## Pull Requests

A pull request should:

- clearly describe what was changed and why;
- include appropriate testing or verification;
- update documentation when necessary;
- avoid unnecessary dependencies or complexity;
- contain no secrets, credentials, or unrelated changes.

Maintainers may request changes, defer a proposal, or decline contributions that do not fit the project's purpose or maintenance requirements.

## Dependencies

New dependencies should have a clear justification. Before adding one, consider whether the requirement can reasonably be met using existing project code or platform capabilities.

## Licensing

Contributions must comply with the license of the repository receiving the contribution.

Do not submit code, assets, documentation, or other material that you do not have the right to contribute.

## Security

Do not report security vulnerabilities through public issues or pull requests.

Please follow `SECURITY.md` for security-related reports.

## Code of Conduct

All contributors and maintainers are expected to follow `CODE_OF_CONDUCT.md`.

## Maintainers

Maintainer responsibilities, project ownership, and organizational decision-making are described in:

- `GOVERNANCE.md`
- `MAINTAINERS.md`

---

> **Prefer the smallest clear solution that solves the real problem.**

Thank you for contributing to WhiteDragon-dev.
